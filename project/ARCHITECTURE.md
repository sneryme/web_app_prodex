# Архитектура

## Решение

Модульный монолит: Django/DRF для доменной логики и API, React/TypeScript для интерфейсов, PostgreSQL для источника истины, Redis/Celery для фоновых задач и генерации документов.

## Доменные модули

- `identity`: роли, сессии, токены и audit events.
- `organizations`: юридические лица, лицензии, потоки и настройки агрегации.
- `participants`: анонимный профиль, согласия, прогресс и жизненный цикл токена.
- `assessments`: версии методик, вопросы, ответы и scoring.
- `reporting`: персональный отчёт, агрегаты, PDF/XLSX и контроль утечек.

## Принципы данных

Ответы отделяются от организационного контура. Связь токена и отчёта доступна участнику, но не работодателю. PRODEX по умолчанию видит операционные метрики, а не индивидуальные психологические ответы.

## Масштабирование

Сначала один backend и один worker. При росте нагрузки фоновые задачи и reporting можно выделить отдельно без изменения публичного API.
