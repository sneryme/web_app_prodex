# ИИПБ v0.1 от 16.11.2026

Источник требований: предоставленные заказчиком `ИИПБ_методические_рекомендации.docx`
(разделы 3–7, приложение Б) и `ИИПБ_калькулятор.xlsx` (листы «Калькулятор», «Опорные точки»).
Новая методология заменяет запрет на сводный показатель в прежнем ТЗ только для
версии `iipb-0.1`. Другие формулы и смешение версий не допускаются.

## Маршрут

Участие добровольное, от 18 лет, с возможностью самостоятельно заполнить формы.
Информирование (включая возраст и ограничения) и согласие на обработку сведений о здоровье
подтверждаются отдельно; в журнале хранится версия `iipb-0.1`. Старое согласие `v1`
не заменяет информирование о новой методологии.

Порядок: HADS (14) → Спилбергер–Ханин (20 СТ, затем 20 ЛТ) → EQ-5D-5L (5) → VAS (1).
Порядок опросников контролируется сервером. Все вопросы обязательны. Заполненный опросник
закрывается для изменения; полный этап сохраняется как первый неизменяемый замер.
Сериализация сохранения ответов блокировкой токена предотвращает гонку при завершении этапа.
Одна пара замеров на комплект; для нового курса нужен новый комплект/маршрут.

После входного этапа участник сразу получает индекс, уровень, заключение, флаги и ЛТ.
Повторный этап открывается сервером через 7 полных суток после завершения входного замера.
До этого вопросы итогового этапа не выдаются и ответы не принимаются. Итоговый замер проводится
после последней процедуры, вне сеанса и не сразу после него, в сопоставимых условиях.

## Расчёт

Десять обязательных целых значений: HADS-A/D 0–21, СТ/ЛТ 20–80, пять измерений EQ 1–5,
VAS 0–100. Пропуски, дроби, NaN, бесконечность и значения вне диапазона запрещены.
LSS — сумма пяти уровней EQ, диапазон 5–25; тариф полезности EQ не используется.

| Показатель | Опорные точки (балл → %) |
| --- | --- |
| HADS-A и HADS-D | 0→100, 7→75, 10→50, 21→0 |
| СТ | 20→100, 30→75, 44→50, 80→0 |
| LSS | 5→100, 7→75, 10→50, 25→0 |
| VAS | 0→0, 40→50, 57→75, 100→100 |

Между точками — линейная интерполяция, вне опорного диапазона — ограничение крайним значением.
Домен тревоги A=(s(HADS-A)+s(СТ))/2, депрессии D=s(HADS-D), здоровья H=(s(LSS)+s(VAS))/2.
ИИПБ=round((A+D+H)/3). Промежуточные значения не округляются. Перед окончательным
арифметическим округлением (0.5 вверх) среднее приводится к 6 десятичным знакам.

Уровни по округлённому индексу: I 75–100 (сохранное благополучие), II 50–74 (лёгкое снижение),
III 25–49 (умеренное снижение), IV 0–24 (выраженное снижение).

R1 HADS-A≥11, R2 HADS-D≥11, R3 EQ AD≥4 заменяют заключение на
«Требуется консультация специалиста» при любом индексе. Сам индекс и уровень сохраняются.
Y1 СТ≥45: повторная оценка через 1–2 недели; Y2 VAS<40 и Y3 любое MO/SC/UA/PD≥4:
консультация терапевта. Жёлтые флаги не меняют индекс и заключение.
ЛТ: ≤30 низкая, 31–44 умеренная, ≥45 высокая; только фоновый маркер.

Ключи STAI в новой версии: СТ обратные пункты 1,2,5,8,10,11,15,16,19,20 (+50);
ЛТ обратные пункты 1,6,7,10,13,16,19 (+35). Варианты обратных пунктов уже содержат
баллы 4,3,2,1: константа повторно не прибавляется. ЛТ-13 исправлен только в новой версии.

Динамика: Δ=после−до в п.п.; Δ%=100×Δ/до, при «до»=0 — отсутствует.
Указываются смена уровня, флаги и ЛТ каждого замера. ЛТ исключена из карточек динамики.
Новый красный флаг, снижение уровня или сохранение Y1 требуют обращения к специалисту;
сохранение Y2/Y3 — к терапевту. Порог достоверного изменения ИИПБ не установлен;
без контрольной группы изменение нельзя приписывать терапии.

Контрольный пример: 9/6/46/48/1/1/2/2/3/60 → 66, II, Y1;
6/4/35/47/1/1/1/2/2/75 → 79, I; Δ=+13 п.п., +19.7%.

## Хранение, доступ и группы

`TestBundle.methodology` выбирает расчёт. `IIPBResult` хранит версию, дату версии, время замера,
индекс, уровень и JSON с десятью входами, подындексами, доменами, флагами и версиями опросников.
Снимок создаётся один раз; повторный расчёт его не заменяет. Начатые исторические комплекты
можно завершить даже после снятия их с публикации. Ответы старого EQ-5D-3L не преобразуются в 5L.

Работодатель получает только агрегаты выбранного комплекта и версии: число замеров,
средний/медианный ИИПБ, распределение уровней, число участников с флагами и количества флагов,
фоновое распределение ЛТ. По совпадающим парам — средняя/медианная Δ и количества направлений
изменения. Индивидуальные входы, снимки и токены не попадают в dashboard, сравнения и экспорт.
Порог публикации не менее 5, отдельно для каждого этапа и для пар; настройка потока может его
увеличить. Отсутствующий результат не заменяется нулём.

Те же агрегаты доступны в PDF, XLSX и CSV. Контакты специалиста и терапевта задаются
в Django Admin в организации и выдаются только участнику. Если они не заполнены,
интерфейс предлагает уточнить их у координатора.

## Подключение и пределы готовности

Для технической проверки существует отдельный тестовый участник (`is_test=True`):
`python manage.py create_test_participant` создаёт его в организации «Тестирование ИИПБ»
с подготовленным синтетическим входным замером. Для него итоговый этап доступен сразу,
после подтверждения согласий. Реальные даты сохраняются, эти данные не входят в групповые
показатели, сравнения и экспорт. Публичный API не позволяет установить тестовый признак;
у обычных участников действует интервал 7 суток.

```bash
docker compose up -d --build
docker compose exec backend python manage.py migrate
docker compose exec backend python manage.py seed_iipb_methodology
```

Команда создаёт новый комплект, назначает его существующим организациям и снимает с публикации
стандартные старые `prodex-v1`/`dummy-bundle`, сохраняя их историю и не меняя произвольные комплекты.
Для новой организации комплект назначается через Django Admin. Повторный запуск не меняет вопросы
и ответы опубликованной версии. Правки формулы/ключей/форм оформляются следующей версией.

Присланная методичка — проект для обсуждения, а не подтверждение валидации и лицензий.
В ней нет самих лицензионных цифровых бланков. Новый набор EQ-5D-5L реализован как цифровой
черновик пяти уровней; тексты HADS/STAI перенесены из имеющегося набора с указанным исправлением
ключа ЛТ. Перед производственным использованием методолог должен сверить точные формулировки,
ключи и цифровые лицензии с бланками правообладателей (§§7.3, 9), утвердить текст согласия и
заполнить маршруты к специалистам. Программные проверки не являются валидацией самого индекса.
