# Сценарии UI/E2E-тестов

Источник требований: ТЗ «Комната ПЭЗ. Digital» (краткое), FR-01…FR-12, и `PROJECT_RULES.md`.
Автотесты лежат в `e2e/tests/` (Playwright), по одному файлу на требование: `fr-NN-*.spec.ts`.

Статусы: ✅ автоматизирован и проходит · ⏳ ждёт реализации функциональности (в коде — `test.fixme`, Playwright показывает его как skipped).

Слои: **UI** — браузер, **API** — запросы к backend, **UI+API** — браузер плюс проверка ответов API.

## Что нужно решить до автоматизации

Часть сценариев нельзя написать, пока нет решений вне кода:

- **FR-05.2, FR-05.3, FR-07.1, FR-07.2:** утверждённые версии методик, эталонные наборы ответов и границы зон интерпретации (методолог, `PROJECT_RULES.md` №5). FR-01…FR-04, FR-06…FR-08 сейчас проверяются на временном опроснике-заглушке (`manage.py seed_dummy_questionnaire`) и черновом scoring (`apps/assessments/scoring.py`), а не на реальных EQ-5D/Спилбергере–Ханине/HADS.
- **FR-09.4, FR-10.3:** порог публикации малых групп (`README.md`, «Важные ограничения»); в модели `Stream.min_group_size` есть временный дефолт.
- **FR-12:** не определено, как аутентифицируются координатор, HR и остальные роли (сейчас в DRF стоит `AllowAny`; модель `identity.StaffProfile` для ролей уже есть, но эндпоинтов входа/прав ещё нет).

```bash
python manage.py seed_dummy_questionnaire   # создаёт опросник-заглушку (НЕ настоящие методики)
```

## Как добавить сценарий

1. Добавьте строку в таблицу выше с новым ID.
2. Добавьте `scenario("FR-NN.M", "…")` в `e2e/tests/fr-NN-*.spec.ts`.
3. Когда функциональность реализована, замените `scenario(...)` на `test(...)` с реальными шагами и поставьте ✅.

## Запуск

```bash
cd e2e
npm install
npx playwright install chromium
npm test            # desktop + mobile
npm run test:ui     # с окном Playwright
npm run report      # HTML-отчёт
```

Перед запуском проект должен работать (`docker compose up`). Адреса можно переопределить: `E2E_BASE_URL` (по умолчанию `http://localhost:5173`) и `E2E_API_URL` (по умолчанию `http://localhost:8000/api`).
